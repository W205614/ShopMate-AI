## 验收报告与证据

报告保留当时的配置、负载、故障与已知限制，不能据此认定当前远端提交已经通过 CI。修改后的发布结果应核对对应提交的 GitHub Actions。

| 报告 | 内容 |
| --- | --- |
| [校招项目完善与角色验收（2026-10-21）](final-acceptance-20261021.md) | 维护恢复、六角色、AI质量与调用预算、首次失败和定向复测 |
| [各角色实际流程验收（2026-10-20）](role-acceptance-20261020.md) | 顾客和员工角色流程、修复结果及证据边界 |
| [稳定性加固与专项验收](stability-hardening.md) | 交易混合负载、备份窗口、资源、供应商故障与恢复证据 |
| [日常默认配置与在线备份验收](default-config-acceptance.md) | 开启请求日志和自动备份后的独立负载与恢复验证 |
| [单店电商 v4 交付验收](reliability-acceptance.md) | v4 迁移、故障、并发与交付边界 |
| [AI 客服接入验收](ai-acceptance.md) | 真实供应商、合成文档格式、确认操作及备份恢复 |

`qa/` 保存上述报告引用的 JSON、代表截图和专项验收材料；`screenshots/` 保存 README 和历史报告引用的界面图片。两者都是证据，不应按“生成文件”整体删除。`visual-inspection.json` 和 `visual-page-audit.json` 对应历史视觉复审，入口见下方归档。
