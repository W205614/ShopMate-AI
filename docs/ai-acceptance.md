## 本轮发现与修复

- 容器原有 Poppler 缺少中文 CMap／字体，补充 `poppler-data` 与中文字体后文字 PDF 可正确提取。
- 扫描资料按短段落切分后丢失实体关联，重复格式副本又挤占上下文；改为同页相邻段落合并及检索前内容去重。新增完整事实与 26 份副本的回归用例。
- 合成资料明确声明“非真实商品承诺”，两道初始题目却要求真实商品信息；模型拒答符合资料边界。验收题改为明确核对合成文档内容，数值、否定词及引用断言保留。
- 无上下文创建会话的 `undefined` 被序列化为 `[null]`，改为零参数，并补充首次发送回归。
- 转人工后继续同步当前会话，关闭、离页或切换身份后停止，防止详情缓存遮蔽人工回复。
- 修复过期模型回答落库、重试绕过队列上限，以及失败重试复用已取消提案的问题。
- 库存清理测试使用同一模拟时钟创建种子；库存恢复浏览器测试明确控制只读恢复时点，保留单次写入和流水守恒断言。
- 新建备份卷目录初始化为运行用户所有；既有目录的修复只针对已经核对归属的隔离验收挂载点。

## 复跑方式

先配置本地 `.env` 的模型凭据，保留原管理员及部署配置。以下示例会创建合成账号、文档和交易，并消耗模型额度，须使用独立项目与空闲端口：

```powershell
$env:AI_ENABLED = 'true'
$env:APP_PORT = '18093'
$env:APP_ORIGINS = 'http://127.0.0.1:18093'
$env:ADMIN_PASSWORD = 'Acceptance123!'
$env:ACCEPTANCE_TAG = 'ai-acceptance'
$env:ACCEPTANCE_LEGACY_COMMANDS = 'false'
docker compose -p shopmate-ai-support-check -f compose.yaml -f deploy/compose.acceptance.yaml up -d --build --wait
$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:18093'
$env:E2E_ADMIN_PASSWORD = 'Acceptance123!'
$env:AI_ACCEPTANCE_ALLOWED = '1'
node backend/scripts/ai-acceptance.mjs
```

脚本需要本机 Node.js 24；模型调用在容器后端执行，格式样例已纳入仓库，不需要重新生成。重新生成样例另需 Pillow、python-docx、ReportLab 及中文字体。脚本拒绝日常端口 18086，默认报告写入被忽略的 `.delivery/ai-acceptance.json`；负面场景的安全拒绝会单独标记。测试后可停止该独立 Compose 项目，保留证据和数据卷。

## 已知边界

- 本轮为单 API／SQLite 部署，无多实例消费、高可用或真实支付物流验收。子进程及容器有资源边界，不代表任意负载下不会过载。
- 图片和扫描件仍可能识别错误；管理员发布前必须核对。没有证据时拒答／转人工，模型自然语言不替代服务端金额与状态校验。
- 后端生产依赖审计无高危或严重条目，存在 3 个中危传递依赖条目，来自 Mammoth CLI 的 `argparse → sprintf-js` 链；当前只使用 `extractRawText`，未调用该 CLI。未采用审计工具建议的破坏性降级，详见 [上游公告](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)。前端生产依赖审计无漏洞。
- 先前关闭日志或备份的负载数字不适用于新增 AI 工作负载；本轮没有重新声称长期吞吐或准确率。

日常部署仅在最终提交 CI 通过后执行升级前备份及容器替换；提交、CI 和最终运行镜像身份由交付记录单独核对。
