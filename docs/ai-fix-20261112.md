# 2026-11-12 AI 定向修复

本记录描述发布前的 main 源码维护与定向复测阶段。当时没有创建新 Release 或覆盖 v0.1.4 镜像；后续用户要求交付 v0.1.5，发布与本机升级以 [v0.1.5 发布记录](release-v0.1.5.md)为准。

## 问题与修改

- 真实模型将 100 元内桌面收纳推荐转成 `search_products` 的 `query="桌面收纳用品"`、`maxPrice=10000`。旧工具把整段中文作为关键词，未命中实际有货的收纳篮。现在复用现有知识分词，保留原关键词并增加多字词的匹配与排序，不新增单字扩展、新依赖或调用预算。
- 政策回答未提供摘录时，旧渲染器会展示整个引用片段，夹带无关条款。现在每个知识引用必须选择完整相关原句；缺少摘录或把商品 ID 当作知识引用 ID 时，进入原有四次请求上限内的格式纠正。仍检查原文及句子边界，不接受截去否定词或条件的片段。
- 定向任务集增加政策无关内容的否定断言；协议假服务同步新摘录契约。合成检查和真实模型结果分别统计。

## 本地验证

- 旧实现的新增回归复现中文搜索、缺少摘录及纠正流程问题。最终直接相关三个文件 46/46 通过，后端类型检查通过。
- 相关七个文件的前一轮检查 80 项通过、1 项因 Windows 缺少完整 Poppler 安装而跳过；不将该项计作通过。此后修改只涉及引用 ID 的格式校验与提示词，已运行最终 46 项定向回归。
- 在独立 Compose 项目、合成账号、订单与知识文档中，通过同一认证限额代理执行真实模型请求。旧发布实现先复现推荐失败；第一次修复后政策两项通过，推荐因模型将商品 ID 放入知识摘录而失败；补充校验和提示后，定向推荐复测通过。三个问题场景为累计覆盖通过，没有重跑完整十二场景，也没有人工质量评分。
- 累计 17 次外部请求，包含对话、Embedding 和 Reranker；所有失败与复测共用本轮 20 次／20 分钟账本，没有重置额度。实际账单未知。

真实测试使用 v0.1.4 基础镜像并只读挂载待验证的两份 AI 源文件，不将它称为已发布的新镜像。没有写入日常业务数据、调用真实支付或发送通知，也没有改变自动备份策略。远端 CI 结果以对应提交的 Actions 为准，本记录不提前代表 CI 通过。

## CI 中发现的入口标准库漏洞

首次 CI 的应用测试、浏览器及 HTTPS 检查通过，但 edge 的原始漏洞扫描发现 Go 1.27.3 中的 CVE-2026-97054，全严重级别门禁失败，后续业务矩阵和源码材料步骤未执行。构建器已固定到官方 Go 1.27.4 摘要，保留原 Caddy 及依赖锁文件；修复依据和验证方式见 [入口安全增补](security/production-edge-security.md#2026-11-12-go-标准库安全增补)。首次失败不计作 CI 通过，最终结果须核对新提交。
