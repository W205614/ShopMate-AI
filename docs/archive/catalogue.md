# 用户端分类与搜索验证

> 历史归档：保留该阶段的实现和验收记录，其中的能力、接口与测试数量不代表当前版本。当前入口见 [文档导航](../README.md)。

验证日期：2026-10-17。

## 交互与边界

首页从服务端公开分类/商品生成分类栏，遵循后台排序并统计在售商品；点击分类即时切换目录，可继续进入相应列表。原来的固定运动分类补位图片已移除，因此初始首页展示 23 件在售商品，含售罄商品，另 1 件下架商品不展示。后台商品和分类变更继续通过既有轮询同步。手机保留可横向滑动的分类入口。

搜索按多词全部匹配，覆盖名称、副标题、描述、材质、分类名、规格，统一大小写及全角英数字。价格单位输入为元，计算使用整数分；筛选按商品最低 SKU 价格，含边界。勾选有货只要求至少一个 SKU 有库存，不改变展示价格含义，不替代结算端校验。

关键词与价格有独立提交边界；每次路由变更从 URL 同步已应用值。支持条件标签单独移除、全部清除、分类/排序重置分页、刷新和前进后退。重复查询参数取第一个；非法价格忽略，非法/小数页码回到第一页，过大页码显示最后一页，未知排序使用推荐优先。未知分类不扩大到全部结果，反向价格区间显示明确提示，用户可清除条件恢复。

## 自动化与容器验收

```powershell
npm --prefix backend run typecheck
npm --prefix backend test
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

在已启动部署执行公开目录只读验收：

```powershell
$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:18086'
npm --prefix frontend run test:e2e -- e2e/catalogue-smoke.spec.ts --output=test-results-container
Remove-Item Env:PLAYWRIGHT_BASE_URL
```

该用例从公开 API 获取实际商品与分类，验证首页分类切换、列表筛选、有货条件、刷新及三种屏幕宽度，检查页面异常和业务 revision 未变。它不会登录、注册、下单或重置部署数据。截图输出到忽略目录 `frontend/test-results-container/`。

GitHub Actions 完整回归后构建隔离的 API/Nginx 容器，在容器地址运行认证测试与目录只读验收。认证测试会创建数据，限定在隔离 CI 部署；日常部署仅执行上述目录只读验收。部署使用原 `shopmate-ai_api_data` 卷，不执行数据重置或卷删除。
