# 单店经营与接口规则（v4）

v4 继续使用单店、单仓、单实例及模拟支付／退款／物流。v3 的联合验收记录作为历史证据保留；本页说明当前行为。

## 库存、付款与退款

新订单创建时通过事务验证报价并预占可售量 30 分钟，报价本身不预占。可售量等于账面库存减去尚未到期的待付款预占；付款核销自己的预占并扣减库存，取消或超时只释放一次。盘点和库存减少不得侵占有效预占。付款仍会校验商品可售状态。

旧待付款订单不补做预占，不更改原到期时间；付款须使用扣除新订单预占后的可售量。旧订单没有新积分与售后期限标志，不追溯赠送积分或缩短既有售后资格。

未发货退款回补对应商品库存；已发货的新订单退货在登记退货收货时创建隔离质检记录，退款与良品质检入库分别执行。良品才能回可售库存，次品保留隔离数量及处置记录。历史售后保留旧兼容行为，不重新回补历史已退款商品。

商品实付优惠按最大余数法分配至订单行，数量退款吸收分币尾差。未发货商品累计全部退款时退还原运费，其他情况仅退商品实付；首版不承担退货运费。新订单默认确认收货后 7 天内可新申请售后，已受理流程不因超过期限中断。服务端 `AFTER_SALE_DAYS` 可设置 1–365 天的演示期限，仅影响此后新订单的快照，不追改历史订单。

## 配送、满减与积分

按配送省份选择规则，`*` 为默认规则；可禁配、固定运费或达到商品折后实付门槛包邮。默认全范围可配送、运费零。规则和金额保存在报价与订单快照中；新地址须填写省份，历史订单地址不修改。

活动为全店限时满减，与优惠券互斥。服务端比较可用优惠，选择减免更多者，同额优先满减以保留优惠券；券的占用、释放和核销仍由订单状态决定。

只有新订单确认收货才产生积分：每满 100 分商品实付得 1 积分，运费不计。退款后按累计剩余商品实付重新计算，差额冲回，余额及流水可查询。积分不抵现、不转让。

## 采购、员工与审计

采购单经过草稿、下达、部分入库、全部入库；已发生入库的采购单不可取消。每次入库有独立回执、库存变动和采购支出，禁止超量、重复规格和重复入库。金额以整数分记录；经营净收支不等于利润。

| 角色 | 写入权限 |
| --- | --- |
| 店主 | 全部经营及员工、配送设置、审计和任务查询 |
| 运营 | 商品分类、商品和优惠活动 |
| 仓储 | 库存、供应商、采购、发货、退货收货与质检处置 |
| 客服 | 会话、FAQ、售后批准或拒绝 |
| 财务 | 退款、财务查询和核对 |

后台菜单与操作按职责显示，服务端再次检查权限；改变员工角色、密码或启用状态会撤销旧会话，不能移除最后一位启用的店主。操作审计不保存口令、Cookie 或请求正文。

## 接口与错误恢复

- `GET /api/bootstrap`：身份及有限初始化数据；`GET /api/collections/:collection`：按身份、条件与页码查询；页大小最大 100。
- `POST /api/actions/:method`：正文 `{args, requestId}`。同身份、同操作、同请求标识返回第一次提交结果；标识与不同参数组合返回 409。普通参数保存 SHA-256 指纹；员工密码命令使用有界 scrypt 慢派生，避免形成快速密码猜解校验器，不保存原始参数。
- `GET /api/requests/:id?method=...`：查询当前身份的提交结果，返回 `{found,result?}`。网络断开或响应丢失后，前端保留恢复标识并先查结果，避免直接重复操作。
- `GET /api/member/points`：本人积分余额；`GET /api/admin/dashboard`、`reconciliation`、`staff`、`jobs`：按权限读取经营汇总、财务差异、员工及后台任务。

商品、分类、优惠券和经营规则编辑提交读取时版本；上下架、优惠启停、收藏使用明确目标状态。409 时保留草稿，重新读取后核对再提交；401 重新登录；429 等待后重试；503 数据库锁定可使用原请求标识重试；未知写入结果先查询，不能自动当作失败重发。

旧版 `/api/state` 已永久退出，固定返回 `410 LEGACY_STATE_DISABLED`；历史验收改用 bootstrap、分页和详情查询，不提供全量读取开关。业务写请求默认必须携带请求标识；仅明确设置 `ALLOW_LEGACY_COMMANDS=true` 时接受省略标识的旧请求，并返回弃用标记。这种兼容请求不具有通用重试去重保证，日常 Compose 默认关闭，旧回归夹具才启用；当前前端全部使用带标识的命令和分领域查询。
