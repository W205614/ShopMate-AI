## 1. 设置编辑可靠性

已先复现草稿被轮询覆盖及空公告被拒绝。编辑期间保留草稿，其他页面修改设置时显示冲突提示；加载最新设置是显式操作。`saveSettings(input, baseline)` 在管理员事务内比较三个设置字段，冲突返回 HTTP 409，拒绝陈旧草稿覆盖。商城名和标语仍必填，公告可为空。恢复演示数据的确认说明包含优惠券、评价、售后、报价、购物车、FAQ 与设置等影响范围，保留账号和登录会话。

验证包括：后端业务与 HTTP 回归（空公告、管理员验证、缺失基线、并发编辑冲突），以及浏览器跨两次真实轮询、远端变更、冲突后恢复、保存失败重试和刷新持久化。类型检查和 ESLint 均须通过；CI 继续运行全部既有测试及独立容器验收。

本地结果：后端 47 项、前端单元 8 项、设置专项浏览器 3 项通过，前后端类型检查和 ESLint 通过。专项包含“手动读取被后发轮询抢占”的响应顺序；设置页直接使用本次读取/保存返回的服务端设置及版本，避免把较旧缓存当作最新值。

本期保留单店、模拟支付/退款/物流和现有客服规则，不引入用户管理、通知、操作日志或 Agent。最终联合测试的实际数量、发现的问题、体验结论、迁移与发布证据在全部功能完成后补充。
