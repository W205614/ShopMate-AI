## 双端界面闭环

`frontend/e2e/joint-commerce.spec.ts` 使用独立管理员和用户浏览器上下文，业务变更通过真实界面提交，GET 用于收集状态证据：

1. 管理员创建长名称商品，验证超过两位小数被拒绝且保留草稿；检查小屏保存按钮焦点和可达性。
2. 创建总量为 1 的满减券；用户注册、领取、立即购买 3 件，错误电话不写入地址，修正后保存长地址。
3. 选择优惠券，模拟服务端已创建订单但浏览器丢失响应；刷新找回唯一订单，不重复下单、不自动付款。
4. 用户付款，未发货时先退 1 件；剩余 2 件正常发货、收货、评价。管理员隐藏/恢复，公开评价昵称脱敏且仅返回展示白名单。
5. 管理员改当前售价，用户再次购买按新价加购 3 件；原订单快照、库存和流水不被加购修改。
6. 已收货后再分两次各退 1 件，分别填写模拟退货信息，管理员收货并退款。
7. 核对财务筛选汇总/CSV、经营概览增量、公开评价、用户私有数据隔离及库存流水。

固定金额不变量：商品单价 100.01 元，3 件原额 300.03 元，优惠 10.01 元，实付 290.02 元。三次退款为 96.67、96.67、96.68 元，累计恰为 290.02 元。仅创建 1 笔订单、1 条下单幂等绑定、1 笔收款和 3 笔退款。库存从 7 扣至 4 后逐次回补至 7，变动为初始 +7、付款 −3、退款 +1/+1/+1；全退评价退出公开评分，券保持已用。

JSON 证据由测试直接导出，包含订单/商品标识、实际下单次数、金额、退款分配、库存、流水条数和未捕获脚本错误。截图仅包含隔离环境测试资料。

## 故障、并发与列表验证边界

| 验证内容 | 所在测试层 |
| --- | --- |
| 下单成功但响应丢失、刷新找回唯一订单 | 联合界面及下单恢复专项 |
| 已成功写入后状态读取失败、未知响应、暂时断网、首次加载失败及会话失效 | 请求恢复专项浏览器/单元测试 |
| 设置另一标签修改、保存冲突、失败重试、轮询不覆盖草稿 | 设置专项 HTTP/浏览器 |
| 库存变化后修改购物车、零库存保留、补货恢复 | 购物车专项及原交易回归 |
| 同键重复库存请求、盘点与付款竞争、支付/超时竞争、重复退款、不超领不超卖 | 后端事务/HTTP 测试及库存恢复专项 |
| 各运营列表超过三页、筛选、刷新、前进后退、末页收敛和跨页详情 | 各工作台专项及通用列表收尾 |
| 跨管理员切换、旧响应/图片解码任务、私有草稿清除 | 编辑及客服专项 |

这不是数据库崩溃、主机断电、真实支付回调、外部物流故障或所有网络故障的覆盖声明。联合用例的断网注入针对下单响应丢失；其余故障按上表的专项结果报告。

初次综合运行期间曾同时运行两个浏览器套件，并修改仍被活动 trace 使用的测试文件，出现 trace 打包损坏；另有两项原交易测试在该次运行超时。打包损坏属于执行方式错误，交易超时不能仅凭时间相关性断定为负载原因。保留失败日志和 trace 后冻结文件、停止并行套件，原交易用例和完整 93 项串行复测均通过，没有放宽原业务断言、增加断言超时或跳过用例。开发服务器在视口调整时仍有 `ResizeObserver loop completed with undelivered notifications` 提示，未做全局屏蔽；生产联合用例另行检查 `pageerror`，不能由此声称所有控制台警告为零。

## 体验检查及保留限制

在桌面 Chromium 的 390、768、1440px 视口检查关键购买/后台页面，覆盖长名称、长地址、打开的表单、错误输入反馈、部分键盘焦点和按钮可达性。截图用于复查真实操作状态，不以页面无横向溢出作为唯一标准；不等于真实手机触控、多浏览器兼容或完整无障碍认证。

已经修复的主要体验问题包括草稿被轮询覆盖、提交成功被误报失败、下单失去恢复入口、库存变化后无法改量、评价跳错页、再次购买数量提示不一致、列表查询/分页与关联定位不足、客服切换清空草稿及旧响应误清新草稿。异常现在提供明确原因和恢复动作；业务服务端仍最终决定资格、金额、库存和状态。

仍保留的限制及后续建议，均未在本期临时扩展：

| 优先级 | 建议 | 依据与当前边界 |
| --- | --- | --- |
| P1 | 人工回复增加请求幂等标识 | 未知回复目前保留原文、要求核对且不自动重发；用户人工重发仍可能重复消息 |
| P2 | 手机后台增加重点列/卡片视图 | 当前宽表在自身区域横向滚动，信息可达但连续处理效率低于桌面 |
| P2 | 选择优惠券后完整展示长规则名称 | 原生选择框小屏可能截断长名称，金额汇总可见，完整阅读便利性仍可提高 |
| P2 | 拆分后台依赖包 | 构建提示后台布局包约 785 kB（gzip 约 248 kB）；尚未做真实网络 LCP/INP 性能基准 |

浏览器草稿仅在对应工作台生命周期内保留，不是离线编辑器。商品图片前端检查可解码性，服务端校验允许来源、Base64、签名和字节大小，未引入完整图片编解码库。SQLite 状态存储及事务适合当前单实例演示规模，未声明多实例扩展能力。财务净收支不代表利润。

## 隔离容器与复现

独立项目、端口、数据卷和镜像标签必须同时隔离。只改 Compose 项目名仍会共享基础配置里的 `:local` 镜像标签，因此验收必须叠加专用覆盖文件。整套注册验收使用新项目/新卷；短时间复用旧卷可能触发每小时 10 次的注册限流，应保留失败证据并换新的隔离项目，不删除日常卷或放宽限流：

```powershell
$env:APP_PORT = '18088'
$env:APP_ORIGINS = 'http://127.0.0.1:18088'
$env:ADMIN_PASSWORD = '自行设置隔离验收密码'
$env:ACCEPTANCE_TAG = 'acceptance-候选提交短SHA'
$env:VCS_REF = (git rev-parse HEAD)
docker compose -p shopmate-joint-final-20261017 -f compose.yaml -f deploy/compose.acceptance.yaml up -d --build --wait
if ($LASTEXITCODE -ne 0) { throw '隔离容器构建失败' }

$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:18088'
$env:E2E_ADMIN_PASSWORD = $env:ADMIN_PASSWORD
$env:E2E_MUTATIONS_ALLOWED = '1'
npm --prefix frontend run test:e2e -- e2e/auth.spec.ts e2e/catalogue-smoke.spec.ts e2e/traditional-container.spec.ts e2e/joint-commerce.spec.ts --output=test-results-container
if ($LASTEXITCODE -ne 0) { throw '隔离验收失败，保留日志与 trace' }
```

以上环境变量只用于隔离命令，结束后删除这些当前进程变量或关闭该终端，避免后续日常部署误用测试配置。已有管理员不会被环境密码覆盖，应使用该隔离卷对应的密码。写入测试不能指向日常 18086。GitHub Actions 使用独立的 `shopmate-auth-ci`、18087 及覆盖文件，并以 `github.sha` 标注镜像。
