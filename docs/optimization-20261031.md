# 对账、AI 表达与质量验证（2026-10-31）

本报告保留发布前第一阶段的验证与限制，后续结果见 [重排及标准构建发布核验](release-20261031.md)。本次按校招展示与本机稳定使用实施，继续保留单店、单仓、单 API、SQLite 和模拟交易。改动在工作区，尚未提交；此前提交的 CI 不算本轮 CI。结构化结果见 [验证汇总](qa/optimization-20261031/summary.json)。

## 实现

- 财务核对使用独立只读进程和一致读快照，按 SQL 聚合检查付款、退款、采购、孤立流水及库存守恒；BigInt 汇总以十进制文本返回，覆盖累计超过 SQLite 64 位整数的历史。并发请求共享一次执行，12 秒到期明确失败，返回前复核财务权限，页面标明核对时间。
- AI 可选择商品比较、检索预算内有货规格后的推荐，以及按用途、材质、价格、库存聚焦回答；价格差由服务端计算。澄清只追问列出的缺失字段，政策摘录要求逐字且完整成句。商品、订单归属、知识版本和确认操作仍由服务端校验，模型自由答复不成为业务承诺。
- 在原 40 条契约之外增加独立 12 条任务问题，记录可回答题分母、误拒答、无降级解决率、澄清及安全拒绝，并生成待填人工评分表。免费契约、新任务集和实际任务浏览器验证已接入工作流；真实模型仅经获准的持久预算代理运行。

## 验证与发现

前后端类型检查、前端 lint、构建及 57 项前端单元测试通过。后端全量首跑 294 通过、1 超时、1 跳过；超时是既有外部备份保留测试，在不改 15 秒阈值的独立复测中通过，累计 295 通过。跳过项因宿主机缺少 `pdftotext`。最终受影响的 32 项另行通过。

混合历史数据验证发现首版聚合连接未使用完整索引；对聚合引用键显式保留 TEXT 类型后，执行计划使用完整连接键，新增 5 万笔含付款流水回归。最终隔离 HTTP 实测如下，包含进程启动开销；它衡量核对期间 API 响应性，不声称核对总耗时低于旧同步版本。

免费协议 40/40、独立任务 12/12。真实模型首轮 11/12：H08 的事实与单位正确，但引用混入未被询问的 FAQ。收紧来源选择提示后仅复测 H08，1/1 通过，累计覆盖 12/12，没有整组重跑。保留首次失败与修复后的原回答、引用及源码摘要，见 [真实模型累计证据](qa/optimization-20261031/ai-live-cumulative.json)。

预算共 44/60 次，包含 30 次对话、8 次 Embedding 成功及 6 次重排 HTTP 402。最终 5 条任务记录检索降级；8 个预先标注可回答的问题中，5 个无降级通过，误拒答 0/8。402 的供应商计费或额度状态需另行核对，本轮没有充值或替换供应商，也没有把降级计为完整上游成功。固定样例不能推导真实用户准确率；人工评分仍待人工填写。

浏览器实际比较／刷新／针对性追问和交易／库存／退款／质检／财务核对两条流程通过。交易初跑受到此前矩阵遗留预占影响，保留原断言，改用全新独立卷复跑通过；未修改库存业务规则。

## 容器与交付边界

标准 Dockerfile 两次构建遇到 Alpine 软件源 I/O 错误，未记作通过。隔离验收复用本机对应 `8f87502` 的现有 API/Web 运行基底，核对后端依赖文件哈希完全相同后复制本次源码与本地构建前端；没有更改依赖或产品 Dockerfile。该结果验证本次应用改动，不能替代一次成功的干净构建。
