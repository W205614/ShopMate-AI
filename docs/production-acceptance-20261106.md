## 修复过程中的失败记录

原有浏览器夹具直接删除账号，新增文件外键使上传后的后续用例级联失败。修复为同一隔离事务内按依赖清理新增表，没有关闭外键。之后两个图片用例仍使用旧 data URI／FileReader 假设，已改为真实上传引用、服务端 WebP 字节及浏览器解码检查。

新渠道对账曾与原内部守恒核对接口重名，已改为独立 `/api/admin/channel-reconciliation`，保留原 `/api/admin/reconciliation` 契约，并增加同时校验返回内容的回归。新增生产对账浏览器用例还纠正了选择器与夹具缺少期初库存流水的问题，最终 6 项在同一轮通过。

备份测试曾超时。诊断显示备份工作进程不到一秒完成，耗时来自测试框架对七份 SQLite Buffer 的深层比较；改为原生 `Buffer.equals` 精确比较，保留七份真实快照、字节不变断言及原超时，备份组 11/11 通过，随后完整后端回归通过。

镜像构建遇到 Alpine 源 I/O 和 npm 官方包连接重置。使用可选 HTTPS 镜像源参数完成候选构建，核对失败包的镜像下载 SHA-512 与原锁文件一致，未关闭 TLS、APK 签名或 npm 完整性校验，未改默认源和日常 `.env`。失败日志保留。

## 安全扫描适用性

前后端运行依赖审计为零已知漏洞；最终 API、Web 容器原始 Trivy 扫描均无发现。扫描使用 Trivy 0.76.2，漏洞库更新于 `2026-11-06T06:50:38Z`，只代表当时结果。

固定 Caddy 2.11.9 镜像的完整原始扫描为 **1 HIGH、2 MEDIUM、3 UNKNOWN**。其中 `CVE-2026-116587` 涉及未修补的 go-jose/v3 私有 RSA JWK 解析。根据上游源码与实际有效配置，该路径在当前只有公网 ACME 客户端和代理、禁用管理接口且未启用 ACME 服务端的部署中不可达；这是本项目的配置评估，不是供应商补丁或镜像整体安全声明。

CI 保留原始扫描，只在固定镜像、Caddyfile、生产 Compose、启动命令及有效模块配置全部通过 guard 后生成临时 OpenVEX，由 Trivy 原生匹配消费。正确配置评估后 HIGH／CRITICAL 为 0，仍保留 2 MEDIUM 和 3 UNKNOWN；改错镜像摘要或子组件版本时仍检出 HIGH 并失败。任何相关配置或镜像变更都需重新评估，详见[完整证据及命令](security/production-edge-vex.md)。
