# 重排 402、标准构建与发布核验（2026-10-31）

## 重排服务诊断

原配置显式选用 `Pro/BAAI/bge-reranker-v2-m3`。在 2026-10-31 核对的 [供应商定价](https://www.siliconflow.cn/pricing) 中，标准 `BAAI/bge-reranker-v2-m3` 列为免费，Pro 为独立收费配置。为本机演示将默认值及本机配置显式改为标准型号，同时保留显式配置覆盖能力。

标准型号的真实探测仍返回 HTTP 402。进一步诊断得到供应商数值码 `30001`，错误内容明确报告账户余额不足，因此换型号本身没有解决该账户的访问限制。完整错误正文和密钥不进入日志或公开证据；只有状态、数值码及余额不足分类被保留。用户处理账户后，在不重置账本的情况下复测，同一标准型号返回 HTTP 200，相关文档排序正确。随后完整一轮真实任务 12/12 通过，8 个可回答问题均无降级通过，误拒答 0/8；两项澄清及两项安全拒绝独立统计。详见 [本轮原始任务证据](qa/release-20261031/ai-live.json)。

## 标准镜像构建

原 CDN 的 community 索引在完整构建中再次出现 I/O 错误，单次下载成功不足以证明构建恢复。对 [Alpine 官方镜像列表](https://mirrors.alpinelinux.org/) 中上海交大及阿里云站点分别执行签名索引更新，均成功。本机显式选择阿里云站点，通过标准 API/Web Dockerfile 做无缓存构建，两个镜像均成功生成；没有复用此前的源码覆盖镜像。

增加构建参数 `ALPINE_MIRROR`，默认仍为 Alpine 官方 CDN。参数保留基础镜像摘要、发行版路径、安全更新及包签名检查；本机 `.env` 的源选择不提交到仓库，CI 默认使用原 CDN。用法见 [开发配置](development.md#配置与访问)。
