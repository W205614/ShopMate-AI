# 企业交付补全与发布记录（2026-11-06）

本记录对应单店生产版之后的交付优化。它与[此前本地生产版验收](production-acceptance-20261106.md)分开；旧报告中的未提交候选、历史镜像和未完成实网联调状态保持原意。

## 本轮变更

- 发布前覆盖运行中、已停止旧容器及保留数据库卷，使用目标镜像生成验证快照和图片恢复集；失败保留维护。
- 解除维护前核对 API/Web 实际镜像 ID、提交标签、健康与生产模式；恢复发布要求维护标记与目标提交一致。
- 配置检查和实际 Compose 使用相同插值配置；公网健康需返回正确 JSON，而非仅 HTTP 成功。
- 补充架构、接口、上线核对、贡献与安全报告入口。GitHub 私密漏洞报告已启用；不承诺 SLA，不虚构支持版本。
- 支付与退款恢复命令绑定请求标识和原参数；回调重复重试不能重置后续失败轮次。
- 物流任务在外部网络前可靠占用尝试预算并绑定任务，进程中断也遵守五次上限。
- 启用短信必须同时配置验证及交易模板，缺失时明确失败，避免静默丢失订单通知。
- 用户正常改密时，同事务撤销旧会话及已签发的验证挑战，旧找回密码凭证不能覆盖新密码。
- 管理员退出同时撤销未完成的 MFA 挑战，并清除新旧 Cookie 路径，退出后的旧挑战不能继续登录。
- 协议正文按版本不可变保存；不能回退复用旧版本号改变正文，原文不可得的已同意历史版本保留占位。协议版本记录纳入备份摘要与恢复校验。
- 同浏览器切换账号后重建安全面板、清理私有草稿并拦截旧异步响应；账号 A 的迟到导出不会交给 B，旧撤销或注销响应不会清除 B 会话。
- 跨标签登录时，旧会话请求可能短暂返回未登录；仅对应用自身发起的鉴权重定向恢复原受保护页面，用户主动打开登录页或退出不会被自动带回。

供应商接入和真实支付、云服务仍按[实网验收清单](integrations.md#本地验证与实网验收)处理。

## 验证与发布证据

本文件是应用变更与验收入口，不将自身提交 SHA 写回源码而形成循环提交。核对某次应用版本先执行 `git rev-parse HEAD`，再按该完整 SHA 查看本仓库的 GitHub Actions；不要把其他提交的绿色结果用于当前镜像。

部署主机的实际本地回归、确切应用提交、CI run URL 与结果、API/Web 镜像与容器 ID、恢复资产、清理回执和最终停止状态，统一记录在私有审计文件 `.delivery/enterprise-release-20261106/final-report.json`。它不随仓库分发，缺少该主机审计时应直接查看对应提交 CI 并重新核验运行状态，不能从本文件推断已完成发布。

| 证据             | 核对方式                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 应用提交与 CI    | 当前应用完整 SHA、该 SHA 对应 Actions run 和实际结论                                                                                                                         |
| 定向本地验证     | 发布 preflight 与 Bash 命令协议 14 项、账号 14 项 HTTP 与 3 项浏览器、支付与外部服务 46 项通过；backend 类型检查、发布 Bash 语法、文档链接与格式检查通过；完整范围见主机审计 |
