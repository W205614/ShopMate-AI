# v0.1.1 物流并发修复

日期：2026-11-09，时区 Asia/Shanghai。本次维持单店、单 API、SQLite 的现有架构，只修复可复现的轨迹合并问题，无新增依赖、接口或数据库迁移。

## 问题与行为变化

查询物流时会先读取运单，再等待供应商响应。如果等待期间较新的签名回调先入库，旧实现仍用查询前的轨迹合并，可能把“已签收”覆盖为“已揽收”，并丢失回调事件。问题影响物流展示，不会推进订单、质检或退款状态。

`backend/src/production/logistics.ts` 现在在合并时读取最新已存轨迹，保留原有去重、时间排序和容量限制。供应商请求仍在 SQLite 写事务外；不增加重试或新工作进程。

## 本地验证

Node.js 24.19.0、Windows，使用内存 SQLite、独立随机端口的 HTTP 供应商与合成凭据，不读取日常业务卷或调用真实供应商。

- 新增回归先在旧实现上失败：预期签收状态 `3`，实际返回揽收状态 `0`。
- 修复后物流恢复、外部协议、账号注销隐私及账号安全四个测试文件共 19/19 通过。新增测试通过真实刷新接口及签名回调，核对轨迹、状态、存储、幂等回执和订单记录保持不变。
- 后端类型检查通过；两工作区生产依赖审计均为零告警，适用于本次检查使用的锁文件及当时 npm 数据库。
- 文档链接与受影响文件格式在提交前检查。最终提交的完整安装、回归、浏览器及镜像门禁，以对应的 [GitHub Actions](https://github.com/W205614/ShopMate-AI/actions) 结果为准；本地定向回归不替代最终 CI。
