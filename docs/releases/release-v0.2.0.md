# v0.2.0 单商家多仓履约

顾客下一张订单、付一笔款，后台按仓分配和发货。结算按配送省份筛选仓库，优先整单同仓。库存不足时可跨仓分配同一个规格，订单详情按包裹显示发货、物流和收货状态。

- 多仓工作台管理仓库、配送范围、实物库存、待发占用、盘点和调拨。仓库员工的订单、发货和退货操作受授权仓限制。
- 下单预占库存，付款转为待发占用，包裹出库时扣减实物。关单确认后释放待付款预占。发货前可改派未被售后锁定的数量。
- 已发商品可按退货仓寄回并分别收货。良品质检入库，次品隔离。未发退款渠道确认后释放待发占用。退款仍按订单原实付金额核算。
- AI 选购在顾客明确给出配送省份时按该地区筛选可配送库存，订单咨询可展示本人订单的包裹进度。

业务数据版本从 5 升到 6。升级应先准备一致快照并验证恢复。旧 SKU 库存迁入默认仓，过去已扣账且未出库的数量转换为实物库存与对应待发占用，迁移登记可追溯的库存期初调整。原订单、支付与退款金额沿用已有记录。部署及回退方式见 [生产部署与恢复](../production.md#备份与失败恢复)。

镜像为 `ghcr.io/w205614/shopmate-ai-api:v0.2.0` 和 `ghcr.io/w205614/shopmate-ai-web:v0.2.0`，支持 Linux/amd64。

本机隔离浏览器验证了一次模拟付款、两个仓库分别发货及逐包确认收货。日常数据库副本从 v5 迁移到 v6，库存可售量及款项核对一致，并用 v0.1.7 镜像验证了独立恢复副本。真实模型使用合成账号和商品，验证了分包查询、无可配送规格提示，以及广东配送场景下 75 元预算内推荐 69 元有货规格。预算内推荐在修正结果判定前两次误报无货，修复后同题复验通过。支付、退款和物流实网接入另行验收。
