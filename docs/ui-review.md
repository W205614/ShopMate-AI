## 发现与修正

| 范围 | 具体问题 | 调整 |
| --- | --- | --- |
| 两种登录页 | 桌面标语接近58px，用户标语分两行；手机登录入口被向下推 | 标语32/24px，表单标题28/24px，压缩演示账号和输入项间距 |
| 商城实用页 | 普通标题最高48px，页面顶部和区块间距过大 | 页面32/24px、分区22/20px，统一边距和章节间隔 |
| 商品详情 | 图片随大列无限增高，购买信息需要较多滚动 | 图片限高520/440/350px并完整展示，保持图片容器与信息栏对齐 |
| 购物与支付 | 金额和空状态抢过商品信息；客服浮层可能遮住操作 | 金额32/28px，缩短空状态，交易页取消悬浮客服 |
| 页脚 | 品牌字最大250px，短页面尾部大量黑白空白 | 品牌26/24px与紧凑服务区，短页自然贴底 |
| 个人中心 | 手机退出按钮前额外67px空隙导致问候语断行 | 去掉多余间距，保留正文及清晰退出入口 |
| 客服 | 消息较少时仍撑出大块固定空白；手机输入区域偏下 | 会话列表与消息区分开响应，输入区可达，长内容内部滚动 |
| 管理通用 | 顶栏、主区、卡片间距叠加；移动筛选挤压 | 标题28/24px，主区28/20px，卡片20/16px，控件换行 |
| 管理设置与客服 | 宽表单右边空白、空会话620px白板 | 表单限制宽度，空会话桌面320px、手机按内容布局 |
| 手机财务日期 | 两个月并排挤压日期、浮层越过视口下沿 | 日历纵排、内部滚动，浮层约束在视口内；实际点选起止日期通过 |

正文为系统无衬线字体，品牌标题保留Libre Franklin；商城正文16px，管理表格14px、说明13px。字号收紧不缩小移动端44px点击目标。白、黑、蓝配色与摄影资产不变。

同一1440×1000视口与相同演示数据下，分类页总高度由2018px降为1367px，含一件商品的购物车由1378px降为1000px，订单列表由2179px降为1726px。它们反映本次样例的纵向密度变化，不是所有数据量下的固定高度。

## 视觉复审记录

ROUND 1

- 第一眼：商品目录和明确操作，但部分实用页仍像展示页。
- 核心句：购物伙伴将商品、订单与咨询上下文连在一起。
- 可操作内容：规则推荐、上下文咨询以及完整模拟购物流程。
- 布局：目录=接触印样 / 分类=图文索引 / 商品=图片与购买信息 / 交易=明细与汇总 / 管理=导航与工作区。
- 最显眼的三个问题：`1440-login` 的两行大标语、`1440-cart` 的标题与巨大页脚、`1440-admin-support` 的620px空面板。按表中方式修正。

ROUND 2（最终）

- 已查看三档首页首屏与分屏、全站缩略图及关键页面原图；额外逐图检查手机日期浮层、商品SKU、客服输入与个人中心。
- 修正限高商品图产生的半列空白、移动会话列表高度、个人中心额外间距，以及短页页脚下方白带。
- 有商品上下文与转人工提示的会话保留至少600px面板，避免收紧空白后消息阅读区被挤成一小条；空会话维持紧凑布局。小屏可正常纵向滚动到输入区，不强求全部内容挤入一屏。
- 对齐、正文可读性、图片比例、按钮反馈与减少动态效果均保留；长表格使用明确的横向滚动区域，页面本身不横向溢出。
- 保守自评：设计7.5、可用性8、创意6.5、内容7.5，加权7.45/10。属于常见商品目录与客服表达，素材背景不完全一致，未因规则通过提高创意评分。
- 适用边界：显式豁免营销页巨大焦点规则；表单与管理应用沿用操作界面惯例。没有合适且真实相关的视频，保留无视频WARN。

## 重建检查

在仓库根目录运行（先通过Docker启动项目，或设置 `PLAYWRIGHT_BASE_URL` 指向开发服务）：

```powershell
node frontend/scripts/audit-pages.mjs after
node frontend/scripts/capture.mjs
```

`audit-pages.mjs` 使用本机Edge（Windows）或Playwright Chromium，输出视口截图和标题/高度/横向溢出测量；输出目录已忽略，不将每次临时截图提交仓库。`before` 参数只负责另存一组，比较旧版时需让目标地址实际运行旧版。

业务回归、skill检查及容器验收结果见 [验证记录](verification.md)。页面截图检查不能代替真实用户可用性研究或服务端安全验证。
